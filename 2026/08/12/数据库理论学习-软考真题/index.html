WHERE 是在分组之前对原始行进行筛选；HAVING 是在分组之后对组（部门）进行筛选。

  • WHERE COUNT(姓名) > 2：SQL 的执行顺序是 FROM → WHERE → GROUP BY → HAVING。当数据库执行到 WHERE 时，还没开始分组，此时 COUNT(姓名) 是整个表的总人数（比如 100 人），而不是某个部门的人数。此外，绝大多数数据库（如 Oracle、SQL Server、PostgreSQL）根本不允许在 WHERE 里直接使用聚合函数，会直接报语法错误。❌
  • B. WHERE COUNT(DISTINCT(部门)) > 2：同样犯了两条大忌。一是 WHERE 里不能用聚合函数；二是算的是“总共有多少个不同的部门”（比如一共 3 个部门），跟“部门内的员工人数”毫无关系。❌

DISTINCT查询结果中去除重复的行，只返回唯一的、不同的值

  • HAVING COUNT(DISTINCT(部门)) > 2：大错特错。既然已经写了 GROUP BY 部门，那每一个组里“部门”的值都是一样的。比如“人事部”这个组里，所有行的部门都是“人事部”，COUNT(DISTINCT 部门) 在这个组里计算出来永远是 1。这相当于在问“这个组里包含几种不同的部门”？答案永远是一种，根本判断不了人数。❌
  • 也就是COUNT(部门)：数的是这一列有多少行记录（有 100 条员工记录，结果就是 100，包含重复值）。COUNT(DISTINCT 部门)：数的是这一列有多少种不同的值（100 个员工分属 3 个部门，结果就是 3）。

给定关系模式 R(U, F)，其中：U为关系模式R中的属性集，F是U上的一组函数依赖。U = {A1, A2, A3, A4}，F = {A1→A2, A1A2→A3, A1→A4, A2→A4}。

主键应为（A1），函数依赖集F中的 （A1→A4） 是冗余的

1. 求（主键）

已知函数依赖集：

  • A₁ → A₂
  • A₁A₂ → A₃
  • A₁ → A₄
  • A₂ → A₄

计算 **A₁ 的闭包 (A₁⁺)**：

  • 初始：A₁⁺ = {A₁}
  • 由 A₁ → A₂，加入 A₂ → {A₁, A₂}
  • 由 A₁ → A₄，加入 A₄ → {A₁, A₂, A₄}
  • 现在有 A₁ 和 A₂，利用 A₁A₂ → A₃，加入 A₃ → {A₁, A₂, A₃, A₄}
  • 已包含全部属性 U，所以 A₁⁺ = U

因此，单独属性 A₁ 就能决定所有属性，且不包含多余属性，所以 A₁ 是唯一的候选键，也就是主键。

其他选项都是包含 A₁ 的超集，不是最小键，所以不选。

2. 判断冗余的函数依赖

检查每个依赖是否能由其他依赖推出（利用 Armstrong 公理）。

  • A₁ → A₂：无法由其他依赖推出，不是冗余。
  • A₁A₂ → A₃：这是唯一能推出 A₃ 的依赖，无法由其他依赖推出，不是冗余。
  • A₁ → A₄：可由 A₁ → A₂ 和 A₂ → A₄ 通过传递律推出（A₁→A₂，A₂→A₄ ⇒ A₁→A₄），所以该依赖是冗余的。
  • A₂ → A₄：无法由其他依赖推出，不是冗余。

因此冗余的是 A₁ → A₄

给定关系R（U, Fr）其中，属性属U={A, B, C, D}，函数依赖集Fr={A→BC, B→D}；关系S（U, Fs），其中，属性集U={A, C, E}，函数依赖集Fs={A→C, C→E}，R和S的主键分别为（ A、A ），关于Fr和Fs的叙述，正确的是（C）

A. Fr蕴含A→B, A→C，但Fr不存在传递依赖

B. Fs蕴含A→E, Fs存在传递依赖，但Fr不存在传递依赖

C. Fr, Fs分别蕴含A→D, A→E，故Fr, Fs都存在传递依赖

D. Fr蕴含A→D, Fr存在传递依赖，但是Fs不存在传递依赖

主键（候选键）是能决定所有属性的最小属性集，用闭包来判断。

  • 对于 R（U={A,B,C,D}，F={A→BC, B→D}）：
    计算 **A 的闭包 (A⁺)**：
    • 初始：{A}
    • 由 A→BC，得 B、C → {A,B,C}
    • 现在有了 B，由 B→D，得 D → {A,B,C,D} = 全集 U
      因为 A 单独就能推出全部属性，所以 R 的主键是 A。
  • 对于 S（U={A,C,E}，F={A→C, C→E}）：
    计算 **A 的闭包 (A⁺)**：
    • 初始：{A}
    • 由 A→C，得 C → {A,C}
    • 现在有了 C，由 C→E，得 E → {A,C,E} = 全集 U
      因为 A 单独就能推出全部属性，所以 S 的主键也是 A。

2. 判断传递依赖

传递依赖的定义：在关系模式中，如果存在 X → Y，Y → Z，且满足：

  • Y 不包含 X（即 Y 不是 X 的子集）

  • Y → X 不成立（即 Y 不能反过来决定 X）
    那么称 Z 传递依赖于 X（即 X → Z 是传递依赖）。

    【后不含前，后不推前】

分析 Fr（R 中）：
  • 有 A→BC，根据分解规则，可得 A→B 和 A→C。
  • 还有 B→D。
  • 串联起来：A → B → D。
  • 检查条件：B 不包含 A，且 B 不能推出 A（因为不存在 B→A），所以 A→D 是传递依赖。因此 Fr 存在传递依赖。
分析 Fs（S 中）：
  • 有 A→C 和 C→E。
  • 串联起来：A → C → E。
  • 检查条件：C 不包含 A，且 C 不能推出 A（因为不存在 C→A），所以 A→E 是传递依赖。因此 Fs 也存在传递依赖。
逐个排除选项：
  • A 错：Fr 存在传递依赖（A→B→D）。
  • B 错：Fr 也存在传递依赖。
  • C 对：Fr 蕴含 A→D（由 A→B→D），Fs 蕴含 A→E（由 A→C→E），且两者都存在传递依赖。
  • D 错：Fs 也存在传递依赖（A→C→E）。

Armstrong 公理

Armstrong 公理-3 条基本规则

  • 自反律：若 Y ⊆ X，则 X → Y。（例如：AB → A）
  • 增广律：若 X → Y，且 Z 为任意属性集，则 XZ → YZ。（例如：若 A→B，则 AC→BC）
  • 传递律：若 X → Y 且 Y → Z，则 X → Z。（例如：若 A→B，B→C，则 A→C）

由公理推出的常用规则（方便解题）

  • 合并规则：若 X→Y，X→Z，则 X→YZ。
  • 分解规则：若 X→YZ，则 X→Y 且 X→Z。
  • 伪传递规则：若 X→Y，WY→Z，则 WX→Z。

冗余函数依赖，指的是：在一个函数依赖集 F 中，某个依赖可以由 F 中的其他依赖逻辑推导出来，如果把它删掉，F 的逻辑闭包（即能推导出的全部依赖）不会发生任何改变。

通俗地说：这条依赖是“多余的”，没有它，其他依赖照样能推出它。

冗余依赖

如果“去掉这个结论”，其他依赖照样能推出你的结论，那么就是冗余依赖。
判断方法：去掉它，再求左侧属性的闭包，看结论是否还在闭包里。

对于依赖 X → A，要看它是否冗余，只需：

  1. 从 F 中暂时去掉 X → A，得到剩余依赖集 F’。
  2. 在 F’ 下，计算 **X 的闭包 (X⁺)**。
  3. 如果 A ∈ X⁺（即靠其他依赖能推出 A），则 X → A 是冗余的；否则不是。

例如：F = { A₁→A₂, A₁A₂→A₃, A₁→A₄, A₂→A₄ }哪个依赖冗余？

： A₁→A₄。

  • 去掉 A₁→A₄，剩余 F’ = { A₁→A₂, A₁A₂→A₃, A₂→A₄ }
  • 在 F’ 下求 A₁ 的闭包：
    • 初始 {A₁}
    • 由 A₁→A₂，得 {A₁, A₂}
    • 由 A₂→A₄，得 {A₁, A₂, A₄}
  • 闭包中已经包含 A₄，所以即使没有 A₁→A₄，也能推出 A₄，因此 A₁→A₄ 是冗余的。

而其他依赖，比如 A₁→A₂，如果去掉它，A₁ 的闭包就只剩 {A₁}，再也得不到 A₂，所以它不是冗余的。

判断主键-属性闭包的计算方法

如果有属性从未出现在任何依赖的右边，只出现在左边，那么候选码一定包含这些属性

闭包 X+是指“从 X 出发，通过已知函数依赖能推出的所有属性集合”。计算步骤如下：

  1. 初始化：令 X+ = X（包含自身）。
  2. 迭代搜索：
    • 扫描所有函数依赖（如 L→R）。
    • 如果当前 X+中包含依赖的左侧属性 L（即 L⊆X+ ），则将右侧属性 R 全部加入 X+
  3. 重复步骤 2，直到 X+不再增加为止。

举例（用上面 R 的 A 来演示）：

  • 初始：A+ ={A}
  • 扫描 A→BC：左侧 A 在集合中，加入 B、C → {A,B,C}
  • 扫描 B→D：左侧 B 在集合中，加入 D → {A,B,C,D}
  • 再次扫描，没有新的依赖能触发，结束。得到全集，所以 A 是主键。

判断 R 的整体范式

  • 候选键：(Ti, S)
  • 主属性：Ti, S
  • 非主属性：C, T, Ro, G

① 检查 2NF（是否存在部分依赖）
部分依赖是指非主属性依赖于候选键的一部分（即单独依赖 Ti 或单独依赖 S）。
检查依赖集：没有任何依赖的左侧只有 Ti 或只有 S（所有依赖左侧都是组合或 C、Ro等）。因此不存在部分函数依赖，R 至少满足 2NF。

② 检查 3NF（是否存在传递依赖）
我们需要找一个链条：候选键 → 非主属性 → 非主属性。

  • 首先，由 (Ti, S) → Ro（已知），且 (Ti, Ro) → C（已知），我们可以推出 (Ti, S) → C（因为先得 Ro，再用 Ro 和 Ti 得 C）。
  • 现在有链条：**(Ti, S) → C**，且 C → T（已知）。
  • 这里 C 和 T 都是非主属性，且 C 不能推出 (Ti, S)，所以 **T 传递依赖于候选键 (Ti, S)**。

因此 R 不满足 3NF，最高只能到 2NF。

分解后 R2 的范式

  • 候选码：(S, C)
  • 非主属性：G

G完全依赖于(S, C)，至少是2NF。只有一个非主属性，不存在传递依赖，至少是3NF。唯一的依赖左侧 (学生, 课程) 是超键， 满足 BCNF。

分解后 R3 (S，Ti，Ro, C)的范式

(Ti, Ro) → C , (Ti, S) → Ro

: (Ti, S) → Ro，加入 Ro → {S, Ti, Ro},由 (Ti, Ro) → C，加入 C → {S, Ti, Ro, C} = 全集 U

  • 候选码：(Ti, S)
  • 非主属性：Ro, C

Ro完全依赖于(Ti, S) , 候选键里的属性子集（比如只拿Ti，或只拿S）不能单独推出非主属性 C，所以C也不存在部分函数依赖，满足2NF。(Ti, S) → Ro Ti → C 存在传递依赖，不满足3NF。既然不满足 3NF，也就不用再看 BCNF 了（BCNF 比 3NF 更严格）。

但是即便跳过 3NF 直接看 BCNF，也会发现不满足。BCNF 要求：所有函数依赖的左侧都必须是超键。
依赖 (Ti, Ro) → C：左侧 (Ti, Ro) 的闭包是 {Ti, Ro, C}，缺少 S，不等于全集 U，所以 (Ti, Ro) 不是超键。因此 R3 也不满足 BCNF。

范式判断步骤

判断一个关系模式属于哪一级范式，请按从低到高顺序，满足一条再往后判断：

  1. 1NF：属性是否都不可再分（原子性）？一般都是默认满足。
  2. 2NF：在 1NF 基础上，检查是否存在 非主属性对候选码的部分函数依赖（即非主属性依赖于候选键的真子集）。
    • 若无，则达到 2NF。
  3. 3NF：在 2NF 基础上，检查是否存在 非主属性Y对候选码X的传递函数依赖: X → Y，Y → Z，其中 X 是候选键，Y 和 Z 都是非主属性，且 Y 不能推出 X。（也就是找一个链条：候选键 → 非主属性 → 非主属性，且链条的前两个遵循后不推前）。
    • 若无，则达到 3NF。
  4. BCNF：在 3NF 基础上，检查所有函数依赖的左侧（决定因素）是否都是超键（即是否能推出全部属性）。
    • 若所有左侧都是超键，则达到 BCNF。

超键：

在关系模式中，能够唯一标识一条记录（元组）的属性或属性组合。只要给出的这组属性在整个表里不会有重复值（能区分每一行），那它就是超键。

候选键 = 最小的超键（去掉任何一个属性，就不能唯一标识记录了）。
主键 = 从候选键里选出来的一个。
所以：超键 ≥ 候选键 ≥ 主键（范围从大到小）。

例如：学生表有（学号，姓名，身份证号）。

  • 超键：{学号}、{身份证号}、{学号, 姓名}、{身份证号, 姓名}、{学号, 身份证号}……只要能区分每个人的都算超键。
  • 候选键：只有 {学号} 和 {身份证号}，因为去掉姓名后仍然能区分，它们是最精简的。
  • 主键：如果选了 {学号} 做主键，那它就是唯一的那个。

在函数依赖中，判断“是不是超键”有一个数学标准：
如果属性集 X 的闭包 X+等于全集 U，那么 X 就是超键。

各个范式存在的问题

1NF（第一范式）只保证属性原子性。

  • 存在大量数据冗余，且插入、删除异常严重，修改操作存在不一致性。

2NF（第二范式）消除了非主属性对候选码的“部分依赖”，但遗留了“传递依赖”

  • 残留问题：依然存在较严重的冗余和异常，但比1NF好一些。

3NF（第三范式）消除了非主属性对候选键的传递依赖。

  • 残留问题：冗余大幅减少，异常极少发生，但依然存在。

BCNF：消除了“决定因素不是超键”的情况，要求所有依赖的左侧都必须是超键。

  • 残留问题：针对“函数依赖”而言，冗余和异常基本被彻底消灭。
  • 特殊情况（极少数）：BCNF依然可能存在由多值依赖或连接依赖引起的冗余（这已经是4NF和5NF的范畴了）。例如，一个教师教多门课，又指导多个项目，即使满足BCNF，表里依然会有大量重复，但这时插入/删除异常已极其轻微，且不属于常规函数依赖导致的问题。
